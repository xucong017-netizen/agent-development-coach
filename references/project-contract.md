# 项目进度与交付契约

在用户选定的项目目录下使用 `agent-design/`。不要把学员数据写回技能安装目录。项目切换时分别保存状态。

## teaching-state.json

复制 `templates/teaching-state.json`，按实际对话填写。UTF-8，`schema_version=1`。

- `title`：业务项目名称；`mode`：学员共创 / 教师演示 / 代码实践。
- `delivery`：设计与代码 / 仅设计 / 设计代码与本地运行。
- `current_module`：当前模块的 id。
- `design_status`：进行中 / 需复核 / 设计完成。
- `decisions`：业务范围、路线、输入输出、模型、提示词等汇总对象；字段保持稳定，以实际需要增加。
- `modules`：保留模板中全部 15 个模块。`status` 取 `pending`（待填写）、`active`（进行中）、`done`（已完成）、`skipped`（本次不采用）、`review`（需复核）。`decision` 写具体决定，`origin` 写学员决定 / 助手建议 / 演示假设，`check` 写小检查证据。可选模块不采用时必须有理由；`skipped` 不算运行能力已实现。
- 每模块 `graph` 有 `nodes` 与 `edges`：节点 `{id,label,x,y,kind}`，边 `{from,to,label}`；id 使用英文字母开头的字母数字下划线连字符。`x,y` 为可选像素坐标。`graph_kind` 写教学示意或项目结构，未填写时为教学示意。
- `agent_graph`：实际业务运行图，节点 ID 与节点契约一致。尚未设计时空数组；不要凭空补完整图。
- `trace`：明确标注模拟或真实执行的轨迹，记录 `{step,node,input,update,output,basis}`。`node` 对应业务图节点 ID。不得写密钥、个人敏感原文和隐含思考过程。
- `open_questions`：未决项字符串列表；用“阻断：”或“实施待办：”明确影响。
- `implementation`：`status` 取未开始 / 生成中 / 已生成未运行 / 运行已验证；`verification` 写真实证据或限制，不随设计状态自动变更。
- `teaching_version`、`file_catalog`、模块 `presentation_status` 与 `artifacts`：按 [成果展示规范](visible-work.md) 记录实际文件、正文/代码、逐块解释与验证证据。业务 done 不等于成果 shown；恢复旧项目时补展示，不重置设计。

完成一个模块后更新其状态、结论、图和检查证据。根据新决定修正总图。修改上游需求时，将受到实质影响的下游模块置为 `review`，保留旧结论并解释需修改之处；无关模块继续保留。依赖关系通常为：任务和输入影响全部；提示词/工具/知识影响节点与评估；状态影响节点、路由及恢复；边与路由影响循环、审核、测试和总交付。按实际影响判断，不机械重做全部。

无文件工具时在对话中给出可复制状态快照；明确“尚未落盘”，恢复时请用户提供已保存快照或使用当前上下文。写文件成功才说“已保存”。

每次完成还应更新成果和展示记录，文件或正文变更后补讲改变部分。最终展示完整文件目录和用途，确认没有未展示成果再结束课程。

## 最终交付

1. `agent-design.md`：业务目标、范围、成功条件、路线理由；15 模块采用/不采用决定；输入输出样例；完整系统提示词；资料、记忆、终止、审核、异常处理策略；未决项。
2. `architecture.mmd`：完整 Mermaid 运行图，包括 START、END、缺信息、无资料、工具失败及所采用的重试/审核出口。另保存 `architecture.txt` 作为无渲染环境的文字图。
3. `contracts.md`：工具契约、节点读写契约、状态表、条件路由表，名字与总图一致。
4. `state-schema.json`：业务状态的数据规范，使用 JSON Schema 或明确标注的字段规范；不是课堂进度的模式。若使用消息对象，说明真实实现由框架消息类型管理，不伪装成普通 JSON 字符串。
5. `test-cases.md`：输入、预期路径、可观察结果、通过条件；标注模拟检查或实际测试。
6. `walkthrough.md`：至少一个正常和一个异常输入的逐节点演练轨迹，按可见数据解释行为。
7. `handoff.md`：实施顺序、选择的框架、能力待接入事项、版本验证方法、运行检查、设计与代码状态；没有执行就写未执行。
8. `teaching-state.json` 与 `design-board.html`：进度和看板；无法生成 HTML 时用聊天图/文字图替代，注明限制。

用户要代码时，在项目自己的 `implementation/` 下逐步生成 Python 文件、依赖声明、配置样例及运行说明。只能用环境变量名或空白占位表示密钥。

## 设计完成检查

逐一检查：必需模块 01、02、03、04、08、09、10、11、12、14、15 完成；可选模块 05、06、07、13 完成或有理由地不采用。标准 agent 的内部结构可标注“框架处理”，仍要有概念解释和检查证据。图中每个 ID 唯一，所有边端点存在，节点读字段已有来源；路径可走到 END；所有循环有明确终止；每个采用的工具有错误出口；没有未处理的阻断项。

“设计完成”不等于实现、业务效果或生产上线完成。无真实代码执行不能更改 implementation 为运行已验证。

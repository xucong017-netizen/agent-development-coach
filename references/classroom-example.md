# 课堂案例：课程咨询助手

本例用于教师演示，不代表学员已经选择它。资料、模型回答与执行轨迹均为模拟。先展示学习路线，再按模块展开；教师要求全程展示时可以连续演示，否则停在当前模块。

## 启动一轮的示例

“我们先写任务单。它就像给一位新同事安排工作：服务谁，办什么事，做到什么程度。今天只设计这一部分。

`[需要选课的学员] → [查询并推荐课程] → [有课程、有理由、有出处]`

课程咨询助手可以推荐，但不会替你报名。你也可以选企业知识问答，或说出自己的场景。你想让智能体帮助谁完成什么任务？”

此处等待学员回答；不能接着替他完成另外十四步。

## 教师演示假设

- 用户提供学习主题和问题；主题缺失时追问并结束本轮，下轮重新输入。
- 只查询课堂目录，按资料形成答案，不替用户报名或承诺课程效果。
- 用规则节点保证确定性查询与分支，用模型节点整理表达；因此选自定义 LangGraph，配合 LangChain 模型接口。模拟看板不执行这些框架。
- 工具 `search_courses(topic)` 返回匹配项及出处；无结果与失败分开。
- 不用向量库、跨会话长期记忆、人工审核和业务持久化。讲清用途与未来条件后标记不采用。
- 工具失败直接说明错误，不自动重试。将来接入实际接口时可在合同中加入有上限的重试。
- 字段：`question`、`topic`、`documents`、`answer`、`error`。查询写资料/错误，回答读资料，特殊出口给追问或资料不足提示。
- 图：START → 检查输入；缺主题 → 追问 → END；完整 → 查询目录；失败 → 说明错误 → END；无资料 → 说明不足 → END；有资料 → 生成回答 → END。

## 两条可见轨迹

正常输入：“我想学 Python，有什么入门课？”主题 Python → 检查通过 → 查询得到“Python 入门，课堂目录 A” → 根据资料给出课程和出处 → END。

缺主题输入：“推荐一门课。”主题为空 → 输入检查 → 追问“你想学习什么主题？” → END。没有调用查询工具。下一轮用户补主题后作为新输入继续。

额外演练：主题不在目录中 → 说明资料不足；工具超时 → 说明查询失败；“替我付款报名” → 边界提示。这些是待执行的测试用例，示例看板只保存前两条轨迹，不谎称已经覆盖全部测试。

## 演示后转向学员项目

提醒：“刚才的决定都是课堂假设。现在换成你的场景，我们先写你的任务单。”另建学员项目并用空白模板；不要覆盖示例或把模拟设计默认为学员决定。

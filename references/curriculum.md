# 课程模块：从结构认识到完整设计

本版本按 [四阶段学习与同步协议](learning-protocol.md) 执行：唯一 design 规范自动派生文档；理解检查和实际执行单独记录。旧版手工文件清单仅作历史示例，以当前规范生成的文件为准。框架示例已有真实 LangGraph 节点，设计模拟与真实运行分开。

按需读取当前模块。每项“图示”是起始教学图；填写后替换其中的角色、字段和条件，变成学员自己的设计。验收是一个小任务，不是背诵术语。所有可选结构都先讲作用，再选择采用或不采用。

每个模块的产物都必须按 [成果展示规范](visible-work.md) 当场展示实际正文/代码、文件用途和块级说明；填写完而没有展示不能进入下一步。下表是推荐落点，复用现有文件优先，不要求每个结构新建一个文件，也不创建未采用能力的空文件。

| 模块 | 设计模式展示内容 | 开发教学可对应文件与作用 |
| --- | --- | --- |
| 01 | agent-design.md 的任务与边界段落 | 本步通常没有业务代码，明确说明 |
| 02 | 输入输出契约、完整和缺字段样例 | schemas.py：输入输出字段和校验 |
| 03 | 模型职责、能力与接口选择 | models.py：模型初始化或明确标注的模拟适配 |
| 04 | 完整系统提示词和消息示例 | prompts.py：保存实际提示词常量 |
| 05 | 工具输入输出和失败契约 | tools.py：函数；目录 JSON：模拟资料 |
| 06 | 来源、检索和引用规则 | 已有查询工具或检索文件：取回相关资料 |
| 07 | 字段与生命周期、不采用理由 | 现有图配置/状态：所选记忆方式 |
| 08 | 每个状态字段及更新方式 | state.py：定义共享状态 |
| 09 | 节点读写和失败结果 | nodes.py：节点函数，标出调用工具/模型位置 |
| 10 | 入口、成功路径、出口 | graph.py：添加节点和普通边、编译图 |
| 11 | 路由条件表与各分支例子 | graph.py 或已有路由文件：条件与去向 |
| 12 | 次数、停止、失败上限 | graph.py/相关节点：计数与终止判断 |
| 13 | 保存、审核、批准和拒绝决定 | graph.py/已有配置：检查点、中断及恢复 |

表中 Python 文件名是可选建议。仅设计时不会为了表格生成业务代码；开发时展示实际采用的文件名、位置和完整新增/修改代码块。

## 01 任务、范围与验收 goal

作用：给智能体一张任务单，防止什么都做却没有结果。构成：使用者、触发场景、核心任务、禁止或不负责的事项、成功条件。

图示：`使用者 → 任务单 → 成功标准`。在总图的位置：定义全图的边界，尚不是运行节点。

提问：它主要帮助谁完成什么事？课程例：帮助学员查询课程信息并形成推荐，不替学员报名。

产物：一句任务描述 + 2 项范围 + 1 项排除事项 + 可观察的验收例子。检查：面对“直接替我付款报名”，学员能判断是否超出范围。缺乏真实场景时只写暂定场景。

## 02 输入、输出与架构路线 io

作用：定义接收什么、交付什么，像窗口的申请表和回执。构成：输入字段、缺失字段处理、输出内容、错误或不确定时的回应、框架路线。

图示：`用户问题 → 输入检查 → 智能体 → 结果模板`。

提问：用户最终应得到什么样的结果？例：课程名称、推荐理由、资料出处；信息不足则提问。

产物：1 条完整输入、1 条不完整输入、输出样例；推荐标准 LangChain agent 或自定义 LangGraph 并解释原因。检查：缺少学习目标时不能无依据推荐。路线暂定，完成分支需求后复核。不要把控制器中的缺失输入逻辑只写成模型提示词。

## 03 模型 model

作用：负责语言理解、信息整理和需要推理的决定，像能阅读材料的工作人员。构成：供应商接口、模型标识、输入上下文、工具调用能力、结构化输出能力、响应与预算约束。

图示：`任务 + 上下文 → 模型 → 回答或工具请求`。

提问：先做不需要账号的模拟，还是接入已有模型？不要求学员了解全部供应商。设计阶段可写“待接入”，仍能完成与供应商无关的设计。

产物：模型职责和能力需求；选择模拟或真实接口。检查：模型不能凭空读取企业数据库；工具调用能力需要具体模型和接口验证。模拟输出不是实际模型性能证明。

## 04 提示词与消息 prompt

作用：规定角色、目标、边界和回答方式，像岗位说明书。构成：系统指令、用户消息、资料上下文、工具返回消息、输出约定。

图示：`岗位说明 + 用户问题 + 资料 → 模型 → 符合格式的结果`。

提问：哪些规则必须每次都遵守？例：只按资料推荐；没有资料说明不足；不承诺录取、就业或价格优惠。

产物：贴合业务的系统提示词，附资料不足的回应。检查：让学员解释“不能编造课程价格”如何影响回答。提示词不替代权限控制、字段校验和程序分支；输出格式在程序边界再次校验。

## 05 工具及调用契约 tools

作用：让智能体获取信息或执行明确动作，像工作人员使用查询系统。构成：工具名称、何时调用、输入字段与类型、输出字段、无结果/错误、超时、读写影响。

图示：`模型提出查询 → 参数检查 → 查询工具 → 返回资料 → 模型整理`。

提问：要完成任务，需要访问哪些外部信息或执行哪些操作？无需求可不采用。

产物：每个工具的契约与一条调用样例。例：`search_courses(topic: string) → {items: list, source: string}`；无结果 `items=[]`，网络错误另有错误码，不能混为一谈。只读课程检索适合首课。

检查：课程信息来自工具结果；如果没有结果，不能编造工具成功。向模型暴露业务参数；凭证从运行环境注入。工具调用的 ID 要与结果消息对应，详见代码桥接。

## 06 知识与检索 knowledge

作用：回答前查阅可靠材料，像先翻课程手册再答疑。构成：来源、更新规则、检索查询、相关片段、出处、无结果处理。小数据可用普通查询，不强制向量库。

图示：`用户问题 → 检索 → 资料片段与出处 → 生成答案`。

提问：哪些资料才算可靠，多久更新？例：机构发布的课程目录，查不到就提示咨询工作人员。

产物：资料清单、检索规则、引用形式；或不用知识库的理由。检查：检索拿到的恶意指令只是资料内容，不应成为系统规则。RAG 是检索后生成的模式，不等于微调，也不保证答案自动正确。

## 07 记忆 memory

作用：决定如何记住前文或跨会话偏好，像本次交流笔记和长期档案。构成：会话内消息、跨会话数据、用户/会话标识、保留期限、删除方式。

图示：`本轮输入 + 本会话笔记 → 回答`；长期部分用虚线或标注“可选”。

提问：哪些信息需要记住，记到什么时候？例：本次对话的预算；本课不存长期个人资料。

产物：记忆字段及生命周期。检查：换一个学员或新会话不能看到前一个人的笔记。课堂进度文件不是智能体的业务记忆；本模块只定义业务记忆。

## 08 状态与更新规则 state

作用：给各步骤一份共享工作表。构成：字段名、类型、初始值、读写者、覆盖或合并规则。

图示：`当前状态 → 节点处理 → 局部更新 → 新状态`。

提问：有哪些信息必须从一步传到下一步？例：`question`、`topic`、`documents`、`answer`、`attempts`、`error`。真实工具循环使用消息及其调用 ID。

产物：字段表；选用 LangGraph 时映射成 `TypedDict` 等已验证的状态类型。检查：普通字段默认覆盖；消息列表需要合适的消息更新器，不能每一步意外清空。并发写同字段必须设计合并或消除冲突；无需并发就先用顺序节点。

## 09 节点 nodes

作用：把流程分成职责明确的工作站。构成：名称、输入状态字段、具体动作、输出更新、失败结果。

图示：`输入字段 → 单个节点的工作 → 输出更新`。

提问：这个节点只负责哪一件事？例：检查输入、检索课程、形成回答。一个节点可用模型，也可完全是普通函数；节点不等于模型或子智能体。

产物：每个节点的契约，标注模型/工具/规则类型。检查：回答节点读取的 `documents` 必须由前面的节点写入，或定义为空的合理出口。避免让节点产生未声明字段。

## 10 连线、入口与终点 edges

作用：让工作站按顺序接力。构成：START、来源节点、目标节点、END、数据交接。

图示：`START → 检查输入 → 检索 → 回答 → END`。

提问：哪些步骤一定要先后执行？先画最简单的成功路径。

产物：节点和边列表。检查：所有节点在使用路径中可到达；成功和失败都有可结束的出口；图名与契约一致。学习路线的 15 个模块不能直接当作业务运行的 15 个节点。

## 11 条件分支与路由 routing

作用：让不同情况走不同路线，像路口指示牌。构成：判断字段、互斥条件、目的节点、默认或错误分支。

图示：`输入检查 ─完整→ 检索；输入检查 ─缺信息→ 追问 → END`。

提问：什么条件下要换一条路线？例：资料为空则说明不足，资料存在则生成回答。

产物：条件表，并复核第 02 模块的实现路线。检查：用完整输入、缺字段、无资料三个例子走图。需要自定义路由时优先考虑 LangGraph。选择追问结束本轮，则下一轮重新提交输入；选择中断恢复则在第 13 模块落实，两者不能含糊混用。

## 12 循环、重试与停止 loops

作用：允许有界补救，像检查后修改，但不能一直反复。构成：循环条件、更新计数、最大次数、超时或预算、退出结果、失败出口。

图示：`执行 → 检查 ─失败且未到上限→ 重试 → 执行；检查 ─通过/到上限→ 结束`。

提问：出错后值得再试几次，达到上限交付什么？可以选择不重试；仍画“失败→结束”并说明理由。

产物：正常终止与上限规则；例：初次查询加最多 1 次重试，共最多 2 次调用。检查：计数必须由程序更新；递归限制是兜底，不等同业务重试次数。工具请求要先执行并返回结果，再让模型继续，不能画成只反复调用模型。

## 13 持久化、人工审核与恢复 control

作用：保存业务执行进度，在需要时停下让人决定，像存档和签字。构成：是否保存、保存对象、会话标识、存储方式、暂停点、审核内容、批准/拒绝出口、恢复入口。

图示：`行动提议 → 人工审核 ─批准→ 执行动作；人工审核 ─拒绝→ 取消；运行状态 → 检查点`。

提问：哪些行为必须经人决定？只读咨询示例可以不采用人工审核，本课用普通会话输入而非暂停恢复。

产物：采用或不采用的决定和理由；采用中断时设计批准、拒绝、修改及恢复。检查：内存保存只适合演示，进程结束后不保证恢复；业务中断恢复需要合适的检查点及会话 ID，且恢复前可能重执行节点，因此外部写操作应防止重复。课堂进度保存仍必需，即使业务图不采用检查点。

## 14 输出检查、评估与运行观察 evaluation

作用：检验智能体是否真的完成任务。构成：输出校验、代表性用例、预期路径/结果、通过指标、脱敏观察信息、失败定位。

图示：`测试输入 → 运行或模拟轨迹 → 对照验收标准 → 通过/修正`。

提问：出现哪种错误会让你认为它不合格？至少覆盖正常、缺输入、查无资料、工具失败/超时、越界请求；有循环增加到上限，有审核增加拒绝恢复。

产物：测试表和至少两条逐节点模拟轨迹。检查：标注“模拟”或“真实执行”，记录节点、可见输入摘要、状态更新、输出、依据；不展示模型隐含思考链，不编造测试成功。模型效果需真实样本评估，图检查不能证明准确率。

## 15 整体设计与实施交接 delivery

作用：把全部模块拼成开发者可实施、学员能讲解的方案。构成：完整架构、组件选择、契约、示例轨迹、测试、未决事项、实施计划。

图示：完整业务图 + 本次采用/不采用的组件图。不是简单把局部示意图串起来。

提问：你能沿着图解释一个正常请求和一个失败请求吗？用自己的话即可。

产物：项目契约要求的文件，按需进入代码实践。检查：字段、节点、工具名称和图一致；每个条件有出口；循环可结束；模拟数据和未接入能力清楚；必需项无阻断缺口。待选供应商可作为实施待办，不阻碍与供应商无关的设计完成；声称真实可运行则必须已经接入并实际验证。

# 可视化约定

## 每个结构

使用中文短标签，并只画本步所需的 3–7 个元素。箭头标注传递什么或判断条件。解释一个正常例子如何穿过图。填写前写“教学示意”，填写后写“你的项目结构”。本次不采用的可选结构仍给教学示意，标注未加入业务图。

例如工具：

```mermaid
flowchart LR
    request[模型提出课程查询] --> validate[检查主题参数]
    validate --> search[查询课程目录]
    search --> result[课程列表与资料出处]
    result --> answer[模型整理回答]
```

该图是工作方式示意，并未承诺模型一定调用工具。自定义确定性检索图中，可以由程序直接调用查询函数。

## 逐步形成总图

在首次明确节点前总图保持空白；学员先看到局部结构和学习进度。节点阶段加入职责，边阶段加入成功路径，分支阶段补充出口，循环与审核阶段只添加已选择的结构。每次图改动同步节点契约及路由表。语言模型、工具、规则和人工节点在 HTML 中用不同标签区分；不单凭颜色传递含义。

Mermaid 不可渲染时直接呈现可读文字：

```text
[开始] → [检查输入]
              ├─缺学习目标→ [追问] → [本轮结束]
              └─完整→ [查询目录]
                           ├─查询失败→ [说明错误] → [本轮结束]
                           ├─无资料→ [说明资料不足] → [本轮结束]
                           └─有资料→ [生成带出处的回答] → [本轮结束]
```

对“追问”明确本轮结束、下一轮重新输入；不能暗示自动暂停等待并恢复，除非已实现持久化中断。

## 离线看板

`scripts/render_board.py` 仅用 Python 标准库，把进度 JSON 渲染为自包含 HTML：学习路线、各模块局部图、当前决定、运行总图、逐步轨迹与未决项。HTML 不依赖 CDN，也不把数据发往外部服务。每次更新 JSON 后重新运行脚本；网页本身不会反向保存学员修改。

1.1.0 看板还显示项目文件地图、各模块实际文件内容、逐块代码解释和执行证据。“模块已完成”与“成果已展示”分别显示。读取旧进度没有 artifacts 时提示待补展示，不伪造正文。看板补充聊天讲解，不能替代当场展示实际内容。

节点坐标以像素计。建议间隔约 250 横向、130 纵向，用明确 x/y 避免自动布局的交叉。节点标签每行约 12 字，复杂契约放卡片正文，不挤进图里。自定义复杂图可用框架导出的 Mermaid，但导出 PNG 可能依赖额外组件或在线服务，不设为课堂必需条件。

看板轨迹中的“上一步/下一步”仅回放已保存的可观察输入、更新和输出，需标注模拟或真实执行。没有轨迹时显示尚未演练，不编造执行记录。图是教学与检查工具，不证明智能体已经接入或运行。

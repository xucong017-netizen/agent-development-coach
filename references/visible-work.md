# 每步成果展示：让学员看见做了什么

本版本按 [四阶段学习与同步协议](learning-protocol.md) 执行：唯一 design 规范自动派生文档；理解检查和实际执行单独记录。旧版手工文件清单仅作历史示例，以当前规范生成的文件为准。框架示例已有真实 LangGraph 节点，设计模拟与真实运行分开。

所有教学模式都使用本规范，不限于代码实践。学员应能看到真实成果、找到文件，并解释每个设计段落和代码块的用途。展示对应实际文件：写入后读回，再引用内容。无文件能力时给出可复制正文，状态写“未落盘”。

## 一个结构完成后的展示顺序

1. **本步做了什么**：说明具体改动，如“加入课程目录查询函数”，不能只写“工具模块完成”。
2. **文件地图**：展示实际项目文件树，标注新增/修改/已有/计划。文件表包含路径、用途、本次改动、谁调用它。区分学员项目、业务代码与技能自己的模板/脚本。
3. **实际写入内容**：新建小文件展示完整内容；长文件完整展示本步新增/修改逻辑块，并给实际位置和可打开路径。设计文档展示本次写入段落，JSON 展示字段及具体值。不能只给 diff、片段标题、三点省略号或链接。其他未变化内容可以省略并明确标注。
4. **逐段讲解**：每块讲“为什么要有这一段 → 接收什么 → 做什么 → 返回/保存什么 → 去掉或改错会怎样”。覆盖当前出现的 import、字段、函数、分支、图组装及入口。无需逐行复述简单语法；学员要求逐行时再展开。
5. **对应结构图**：如“查询节点 → implementation/tools.py::search_courses”，说明文件间调用与数据关系。文件不必与节点一一对应。
6. **具体输入输出**：至少一条输入、处理和结果。实际执行后给命令与真实输出；未执行分别写“预期结果”和“未执行原因”。区分模拟资料、本地函数执行和真实模型/框架执行。
7. **理解检查**：问一个关于实际内容的小问题，如“topic 换成目录里没有的词，会得到什么？”再说明下步修改哪个文件，目前哪些能力未接通。

首次启动仍等待学员选择任务。每个新决定对应具体设计材料；从第 01 模块起维护 `agent-design/agent-design.md`，相应阶段增加契约与架构。整堂课只更新进度 JSON 不算完成教学。

## 设计与代码模式

- 仅设计：展示实际任务说明、提示词正文、字段表、工具契约、路由表等；具体值或待填写项清楚。“本步没有业务代码”要说清，不虚构 `.py` 文件。
- 开发教学：当前结构明确后生成可解释的最小代码及必要数据文件，当场展示，不等全部设计结束。有依赖就画调用关系；后续依赖未完成时仅检查可运行部分，标注整体未接通。
- 不采用：展示用途图和具体不采用理由，说明决定写入哪个文档；不为了凑数创建空模块或 `pass`。

## 工具结构示范

技能 `templates/course-example/implementation/` 中有实际源文件。这是课堂目录查询，未调用模型或 LangChain。教师模式可读出实际内容；学员项目需复制或按业务改写。

```text
implementation/
├── course_catalog.json  [新增] 模拟课程资料
└── tools.py             [新增] 加载目录并按主题查询
```

| 文件 | 用途 | 本次写入 | 调用关系 |
| --- | --- | --- | --- |
| implementation/course_catalog.json | 模拟课程数据 | Python 入门与出处 | 被 tools.py 读取 |
| implementation/tools.py | 只读查询 | load_catalog、search_courses、演示入口 | 未来查询节点调用，当前可独立执行 |

接着完整展示两个小文件，逐块解释导入、加载、筛选、返回和 `__main__` 入口，再画：

```text
[主题 topic] → [tools.py::search_courses]
                      ↑ 读取
              [course_catalog.json]
                      ↓ 返回
              [items 列表 + source]
```

执行 `python implementation/tools.py Python` 报告实际输出。目录不存在的主题得到空列表，空输入有错误提示。文件缺失或 JSON 损坏会抛异常，需由后续调用节点处理；不能称已具备完整图的失败出口。这个独立函数不是完整智能体，后续再接入所选框架。

## 记录与恢复

保持 `schema_version=1`，新增字段向后兼容：

- `teaching_version`：`1.4.0`。
- `file_catalog`：实际文件表，条目 `{path,purpose,kind,status,caller}`。path 为项目相对路径。status 为新增/修改/已有/计划未创建/未落盘。
- 模块 `presentation_status`：`pending` 待展示、`shown` 已完整展示、`review` 变更需重讲。初始 pending；实际完成展示后设 shown。
- 模块 `artifacts`：具体产物数组，每条 `{path,purpose,kind,change,content,content_scope,explanations,verification}`。
- `kind`：设计文档 / 业务代码 / 数据文件 / 配置 / 图示 / 进度记录；`content` 为读回的实际正文/源代码；`content_scope` 写完整文件或实际片段位置。
- `explanations`：条目 `{block,why,input,action,output,consequence,graph_node}`，按逻辑块解释，不填泛泛的“处理逻辑”。graph_node 对应业务图节点、概念图元素或“尚未接入业务图”。
- `verification`：`{status,command,expected,actual}`。status 为未执行 / 已实际执行 / 设计检查。没有执行时 actual 为空，不能把预期填成实际。

正文或代码变更后更新内容，将展示状态置 review，补讲改变部分。文件表与实际目录一致，片段与读回文件一致。

恢复 1.0.0 项目时保留设计状态，缺展示记录的模块补 pending。先展示文件地图，优先补讲学员指出部分，再按顺序补其余内容。文件不存在则直说，不从旧的 done 推断已写好或假造正文；已有内容按实际补记录，不重复覆盖。缺材料只询问必要路径，不默认读取其他项目。

## 展示完成条件

实际新增/修改内容、文件用途与调用关系、全部本次逻辑块解释、图对应、输入输出、检查状态都已展示。缺项就在本步补充，不能用“用户说下一步”掩盖遗漏。文件多时分批展示并保留未展示清单；不每轮重复全部历史代码。

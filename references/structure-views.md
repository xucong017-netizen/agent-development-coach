# 每一步怎样对应整体 · 1.6.0

## 三层展示

1. 本步局部运行图：从 design.graph 截取本步作用节点及一跳前后衔接。红色为作用范围，虚线为外部衔接；不生成不存在的业务节点。
2. 整体流程：保留全部业务节点与连接，红色定位当前主步骤的节点/控制连接，其他结构作为参照。多个步骤可以共同作用于同一个节点，例如模型与提示词。
3. 内部教学图：解释结构里的参数、调用、判断与结果。明确标“教学拆解，不是额外运行节点”，可以展开查看；优先按本步实际决定填具体名称与字段。

页面还展示当前决定、控制规则、实际节点对应、逐节点读写字段及源码入口。结构组成可查看配置；历史前后对照只标版本变化，退出对照才能定位当前步骤，不能把当前映射套在历史图上。

## 维护对应关系

design.structure_bindings 以固定的 15 个模块 ID 为键，保存结构对应信息，随项目保存。不要使用固定的示例节点名猜测学员项目。每轮更新业务图或契约时核对并更新相关映射，再执行 --sync。配置说明改变不会改动业务代码，也不会使原运行证据失效；实际节点、契约或业务决定改变仍按正常规则需复核。

```json
{
  "tools": {
    "kind": "runtime",
    "nodes": ["catalog_query"],
    "edges": [{"from": "catalog_query", "to": "query_failed"}],
    "controls": ["读 topic，调用 search_courses；写 documents/source，失败写 error"],
    "summary": "查询课程目录，支持空结果与失败处理",
    "basis": "工具契约 node 与实际调用函数相对应",
    "internal_graph": {
      "nodes": [
        {"id": "args", "label": "检查 topic 参数", "x": 20, "y": 35},
        {"id": "call", "label": "调用 search_courses", "x": 290, "y": 35},
        {"id": "result", "label": "写回查询结果或错误", "x": 560, "y": 35}
      ],
      "edges": [{"from": "args", "to": "call"}, {"from": "call", "to": "result"}]
    }
  }
}
```

kind 可用 runtime（实际运行结构）、configuration（作用于节点的配置）、global（跨整体结构）、not-used（当前明确不采用）。nodes/edges 必须来自当前业务图；已删除的对应关系会显示待修复，不回退为随意高亮其他节点。controls 写具体受控字段、条件或规则；summary 与 basis 是可选说明，实际决定仍以 component_decisions 为准。省略 edges 时按已确认节点派生连接；需要强调特定控制出口时明确列出。

对于工具、模型、路由、循环、输入输出、状态、节点、连接、运行验证和交付，工作台可从现有契约派生已知对应关系；知识检索、记忆、人工介入等只有证据明确才能映射。未登记时显示“待补齐”，不能声称没有能力。不采用与待补齐是两个不同状态。未采用结构可保留教学原理图，但不高亮实际节点。

节点与路由变化时，局部图、整体图、读写表和实现入口都从保存后的同一份设计重新生成。网页有草稿时提示映射以已保存设计为准，保存后重新计算。静态导出包含这些视图，但仍只是离线副本。
